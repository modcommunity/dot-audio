# Box sounds: `DotBoxSounds`

One sound per box event: `spawn`, `approach`, `open`, `reward`, `deny` and `effect_end`. A box type's `sounds` dictionary (a `box` profile key in dot-profile) has one slot per event. A slot is `{sound: <stock id>}` or `{asset: <path>}`, plus `volume` (dB), `pitch_jitter`, `distance` (metres, 3D only) and `ui` (true plays flat, false at the box's position). An empty or missing slot falls back to the stock set, built from `DotAudioSynth` recipes (`DotBoxSounds.stock_recipes()`).

`DotBoxSounds.install(manager)` registers the stock sounds with a `DotAudioManager`; `set_slots(box_id, slots)` replaces one box type's slots (a live profile edit calls it again); `fire(box_id, event, position)` plays a slot; `effect_end(box_id, key, position)` fires `effect_end` once per effect key however many times it is called; `approach(...)` fires on the edge of entering a radius, with hysteresis so standing at the boundary does not repeat. Every fired event emits `event_fired(box_id, event, position, sound_id, handle)`, also when the sink is silent, so a game can mirror it (a subtitle, a light). Playback goes through the manager, so buses, ducking and the null sink used by suites apply. The example `examples/box_sounds_selftest.tscn` holds it.
